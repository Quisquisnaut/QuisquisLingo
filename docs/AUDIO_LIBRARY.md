# Recorded audio library

QuisquisLingo lets a course creator choose `System TTS`, `Recorded MP3 only`, or `Hybrid` audio in Course Editor > Audio Library.

Workflow: in **What do you hear?**, **Spoken text** is the exact requested utterance, not a filename. System TTS sends it to the native speech engine. To use recordings, choose Recorded MP3 only or Hybrid in **Course Editor > Audio Library**, then either place MP3 files in `Documents/QuisquisLingo/Import/Audio` (`Download/QuisquisLingo/Import/Audio` on Android) and choose **Add to the Course > Quick Import**, or use **Add to the Course > Open from…** to pick up to 100 MP3s in the system file dialog; both routes apply the same checks and store the files in the same place. Then tap each recording (**Associate recording**) and enter its **Word or expression**, or pick it from **Texts in this Course**. Exercises resolve their spoken text against these Course-level mappings; there is no per-exercise MP3 attachment.

Since Build 243 a recording is Course media: the clip's `filePath` is `media:<sha256>.mp3`, the SHA-256 of the MP3 bytes, and the file lives in the Course's own folder `QQL_CourseMedia/QQL_<pair>_<sha256(courseId)>/` below application support (`CourseMediaStore`; Build 255 Revision 4, with the Course's language pair such as `EN_IT`, and `QQL_<sha256(courseId)>` until the Course is first stored). Deriving the folder from the stable Course ID keeps it traversal-safe; naming the file by content makes the reference identical on every device and stores identical recordings once. Paths on one device are refused by Course Model v11. Verified Course-version backups copy the Course's media and Restore puts it back; a confirmed save removes files the Course no longer uses, and deleting a Course deletes its folder. Course JSON and learner data exports do not embed MP3 bytes; the Course package (Build 243 Revision 3) carries them.

Imported MP3 files (maximum 50 MB each) are copied into application-owned support storage. Each recording is mapped to one word or expression. Playback segments a requested utterance using longest-match-first matching and concatenates the recordings with a short pause. In Hybrid mode, TTS is used only when a complete recorded sequence cannot be assembled. In Recorded MP3 mode, missing coverage is reported rather than silently falling back to TTS.

The editor checks for orphan MP3 files with no word/expression mapping when the Audio Library is opened manually, during Course Audit, after library changes, and periodically (no more than once every seven days per course when the editor is opened). Deletion is always user-confirmed. Before deletion, the current course is checked again so stale audit results cannot remove a newly used clip.

A clip that still carries its word but whose file has disappeared is not an orphan, so the orphan check never reports it. The Audio Library marks such rows **File missing** instead; delete the recording there to drop its reference, then confirm the Course. A missing file does not block saving: the pre-change Course backup records the gap in its manifest rather than refusing to run, because a file that is already gone cannot be lost by the change the backup precedes. Backup records that do name a copied file keep their strict existence and SHA-256 checks.

Since Build 271 Revision 2 the screen has three icons in its top bar (Help, **Add to the Course**, **Check**), a header that stays in place (the one-line notice, the audio source with one line of explanation, the A–Z bar) and rows without file names. **Associate recording** shows the name the file had when it was imported (`originalFileName`, a label kept with the recording and left out of Export as Publisher Course) and the stored name, plays the recording and, on Windows, Linux and macOS, opens its folder. **Check > Texts in this Course** lists every text the Course speaks, Draft exercises included, with one of four states (its own recording, all parts recorded, some parts recorded with the words still missing, no recording), a search, a switch for the texts without a complete recording, Copy and Save as…; it uses the playback's own matching rule (`AudioSegmenter`). **Check > Unused MP3 files** lists the recordings no exercise plays.

Imported audio files stay outside the Course JSON to avoid inflating it. Because references are already content addresses, the Course package copies the files as they are and rewrites nothing.
