# Recorded audio library

QuisquisLingo lets a course creator choose `System TTS`, `Recorded MP3 only`, or `Hybrid` audio in Course Editor > Audio Library.

Workflow: in **What do you hear?**, **Spoken text** is the exact requested utterance, not a filename. System TTS sends it to the native speech engine. To use recordings, either place MP3 files in `Documents/QuisquisLingo/Imports/Audio` and open **Course Editor > Audio Library > Import MP3**, or use **Open from…** to pick one MP3 in the system file dialog; both routes apply the same checks and store the file in the same place. Then use **Associate recording > Word or expression** for each clip. Choose Recorded MP3 only or Hybrid. Exercises resolve their spoken text against these Course-level mappings; there is no per-exercise MP3 attachment.

Since Build 243 a recording is Course media: the clip's `filePath` is `media:<sha256>.mp3`, the SHA-256 of the MP3 bytes, and the file lives in the Course's own folder `quisquislingo_course_media/course_<sha256(courseId)>/` below application support (`CourseMediaStore`). Deriving the folder from the stable Course ID keeps it traversal-safe; naming the file by content makes the reference identical on every device and stores identical recordings once. Paths on one device are refused by Course Model v11. Verified Course-version backups copy the Course's media and Restore puts it back; a confirmed save removes files the Course no longer uses, and deleting a Course deletes its folder. Course JSON and learner data exports do not embed MP3 bytes; the Course package (Build 243 Revision 3) carries them.

Imported MP3 files (maximum 50 MB each) are copied into application-owned support storage. Each recording is mapped to one word or expression. Playback segments a requested utterance using longest-match-first matching and concatenates the recordings with a short pause. In Hybrid mode, TTS is used only when a complete recorded sequence cannot be assembled. In Recorded MP3 mode, missing coverage is reported rather than silently falling back to TTS.

The editor checks for orphan MP3 files with no word/expression mapping when the Audio Library is opened manually, during Course Audit, after library changes, and periodically (no more than once every seven days per course when the editor is opened). Deletion is always user-confirmed. Before deletion, the current course is checked again so stale audit results cannot remove a newly used clip.

A clip that still carries its word but whose file has disappeared is not an orphan, so the orphan check never reports it. The Audio Library marks such rows **File missing** instead; delete the recording there to drop its reference, then confirm the Course. A missing file does not block saving: the pre-change Course backup records the gap in its manifest rather than refusing to run, because a file that is already gone cannot be lost by the change the backup precedes. Backup records that do name a copied file keep their strict existence and SHA-256 checks.

Imported audio files stay outside the Course JSON to avoid inflating it. Because references are already content addresses, the Course package copies the files as they are and rewrites nothing.
